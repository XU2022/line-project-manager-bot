# 部署指南

下面以Linux、systemd、Nginx和Python 3.11以上版本为例。请先在测试服务器完成验证，再用于真实项目群。

## 1. 准备LINE账号

1. 创建LINE Official Account和Messaging API channel。
2. 保存Channel secret和Channel access token，不要写入仓库。
3. 在Messaging API设置中允许机器人加入群聊。
4. 准备一个公网HTTPS地址，例如`https://line.example.com/webhook`。
5. 将机器人加入测试群，通过webhook事件取得群组ID和成员ID。

首次取得ID的安全引导流程见[LINE官方账号设置](LINE官方账号设置.md)。

## 2. 安装项目

```bash
sudo useradd --system --home /opt/line-project-manager --shell /usr/sbin/nologin linebot
sudo mkdir -p /opt/line-project-manager/state /opt/line-project-manager/config
sudo chown -R linebot:linebot /opt/line-project-manager
sudo -u linebot python3 -m venv /opt/line-project-manager/venv
sudo -u linebot /opt/line-project-manager/venv/bin/pip install .
```

这些命令假设当前目录是已经审查过的仓库副本。

## 3. 创建本地成员配置

复制`config/members.example.json`：

```bash
sudo cp config/members.example.json /opt/line-project-manager/config/members.json
sudo chown linebot:linebot /opt/line-project-manager/config/members.json
sudo chmod 600 /opt/line-project-manager/config/members.json
```

把文件中的虚构ID和名称替换成真实成员信息。该文件不得提交到Git。

## 4. 创建环境文件

创建`/etc/line-project-manager.env`：

```text
LINE_CHANNEL_SECRET=replace_me
LINE_CHANNEL_ACCESS_TOKEN=replace_me
LINE_ALLOWED_GROUPS=C_REPLACE_WITH_GROUP_ID
LINE_REMINDER_GROUP_ID=C_REPLACE_WITH_GROUP_ID
LINE_FALLBACK_TRIGGER_LETTER=H
PROJECT_DB_PATH=/opt/line-project-manager/state/tasks.sqlite3
MEMBER_CONFIG_PATH=/opt/line-project-manager/config/members.json
LINE_HOST=127.0.0.1
LINE_PORT=8646
PROJECT_TIMEZONE=Asia/Tokyo
REMINDER_HOUR=12
MONTHLY_MESSAGE_LIMIT=200
ESTIMATED_PUSH_COST=3
```

```bash
sudo chown root:linebot /etc/line-project-manager.env
sudo chmod 640 /etc/line-project-manager.env
```

`ESTIMATED_PUSH_COST`表示一次群Push预计消耗的消息条数，应根据群内接收人数和实际计费规则设置。

机器人默认通过LINE的真实`@机器人`提及触发。`LINE_FALLBACK_TRIGGER_LETTER`只能填写一个英文字母，在成员无法提及时作为句首备用触发；修改后需要重启webhook服务。

## 5. 初始化

```bash
sudo -u linebot sh -c 'set -a; . /etc/line-project-manager.env; set +a; /opt/line-project-manager/venv/bin/line-project-init'
```

初始化命令只建立数据库和成员，不访问LINE网络。

## 6. 安装服务

```bash
sudo cp systemd/line-project-bot.service /etc/systemd/system/
sudo cp systemd/line-project-reminder.service /etc/systemd/system/
sudo cp systemd/line-project-reminder.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now line-project-bot.service
sudo systemctl enable --now line-project-reminder.timer
```

示例timer使用`Asia/Tokyo`的12:00。如果你的`PROJECT_TIMEZONE`或`REMINDER_HOUR`不同，请同步修改timer中的时区或小时。

检查：

```bash
systemctl status line-project-bot.service
systemctl status line-project-reminder.timer
curl http://127.0.0.1:8646/healthz
```

## 7. 配置HTTPS

以`config/nginx.example.conf`为起点，替换示例域名和证书路径。Nginx必须原样转发请求体和`x-line-signature`请求头。

配置完成后，在LINE Developers Console将webhook URL设置为：

```text
https://line.example.com/webhook
```

点击Verify确认LINE能够取得HTTP 200响应。

## 8. 上线前检查

- `.env`和真实成员配置不在Git中
- webhook只能通过HTTPS访问
- Channel secret和access token权限受限
- 机器人只允许进入预期群组
- 使用测试任务验证新增、查询、完成和提醒
- 确认`ESTIMATED_PUSH_COST`与群规模一致
- 检查月度消息额度后再启用timer
